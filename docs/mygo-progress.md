## 第一批落地（M0/M1）

- 用户明确允许将迁移依赖下载到全局目录。MyGo 固定 `v0.7.4`，源码 commit `9bd34e1eb9525d9a1fe698aadc964c49c8ff8e7e`；依赖在 Go 默认全局模块缓存，未另建依赖缓存或安装 VM。未安装全局 MyGo CLI、Bun 或新的 npm runtime：M1 使用框架注入的官方 `mygo.call/on`，无需前端打包；正式 TypeScript 客户端生成尚待验证。
- 新增 `cmd/icetudio-mygo` 独立验证入口，`internal/desktop` 为 Native 布局和只读投影，frontend 的 Go 资源包仅嵌入独立页面及已在项目内的 GridSound 源码子集，不嵌入普通 React App 或 FL 图片。
- Native 实现工程浏览、编排轨道/Clip 绘制、Clip 选择、上下分隔调整、Agent 面板显隐，以及 Native Markdown 表格/代码块样例。普通 React 外壳未复制进新窗口。
- 无参数启动（包括双击）或 `--preview` 使用明确标注的只读视觉 fixture，不启动宿主、模型或 MCP；`--data` 要求显式绝对路径，复用 host.Start、数据目录锁和 app.Service 查询，后台读取后回主线程更新，过时查询结果丢弃。
- WebView 只绑定 `PianoPreview.Context` 一个只读方法。Native 选中片段后发 typed context event，页面重读投影。投影携带 generation 和稳定目标 ID，复制音符切片，拒绝共享可变数组；显示前 16 四分拍起点范围内的最多 512 个音符，并明确显示数量限制。它不是完整卷帘编辑入口。
- 音乐编辑/播放、关闭保护、普通设置和实际 Agent 交互尚未接入；Piano Roll 保留引擎但阻止写手势，不把临时修改冒充已保存。原 Wails、全部服务和业务能力未删除。Agent 执行内核没有改动。
- MyGo 要求 Go 1.27.3，已同步 go.mod、CI 和 README；相关 Go 传递依赖由模块解析更新。MyGo MIT 通知保存在 licenses/MyGo-MIT.txt，最终安装包全部传递依赖和素材义务仍待 M6 审计。

## 复现入口

在仓库根目录执行（Go/运行库已具备时使用离线依赖；新下载仍遵守许可规则）：

```bash
npm --prefix frontend run build:mygo
env GOPROXY=off GOTOOLCHAIN=local go build -o bin/icetudio-mygo ./cmd/icetudio-mygo
bin/icetudio-mygo
env GOPROXY=off GOTOOLCHAIN=local ICETUDIO_MYGO_NATIVE=1 go test ./internal/desktop -run '^TestMyGoNative' -count=1 -v
```

读取现有工程可用 `bin/icetudio-mygo --data /实际数据目录绝对路径`。这不是纯数据库查看器：它使用正常 host 启动、恢复和音频/扩展初始化；后续 M2 增量已启用静音/独奏及共享撤销/重做，第三批卷帘也可提交音乐修改；这些操作会修改对应工程，原 M1 的只读限制不再适用于 --data 交互入口；不要与原宿主同时运行，也不要为了验证复制/清理用户数据。启动锁失败时明确退出。当前日常入口为根目录构建的 bin/icetudio；此段原入口说明已由收尾记录替代。

自动分层截图可用 `bin/icetudio-mygo --preview --smoke-dir /tmp/icetudio-mygo-review`，该目录仅为单次验证输出，不是依赖或构建缓存。--smoke-dir 对应只读自动化检查，完成后自动退出。

## 2026-11-03 第三批：复用完整卷帘编辑接入 MyGo

状态：M2 局部闭环完成，M0–M6 整体未验收。用户要求在迁移完成后删除 Wails；本批未删除框架，因为 Native Arrangement 手势、工程管理、设置、实际 Agent 与其他保留入口尚未替换完成。

### 实现与边界

- WebView 改为独立 React PianoPage，直接复用现有 usePianoRoll、投影、GridSound 和 MusicInputs 草稿机制；没有重写钢琴卷帘。普通 App/Arrangement/设置/Agent React UI 不进入该页面。绑定类型目前仍有对现有生成模型的 type-only 引用，不能因此宣称构建链已完全脱离 Wails；产出的卷帘 JavaScript 未发现 Wails runtime 字符串。
- MusicServices 与 musicClose 将卷帘所需服务和关闭上下文从旧 Wails 载体抽出；旧 CloseGuardProvider 注入原服务，原浏览器编辑入口继续可用。M1 临时 mygo-piano.html/js 已由独立页面替换并删除。新的 `frontend/mygo-web/assets` 是忽略的构建产物，先执行 `npm --prefix frontend run build:mygo` 再构建 Go，Task 的 mygo:build 和 CI 已加入此顺序。
- 实际页面获得所选片段的完整音符/控制事件及 tempo/meter，沿用原分页和视口投影。PianoContext.Notes 的 512 项上限仅保留为旧烟测样本，**不是编辑数据上限**。原生编排仍是局部显示，不能据此宣称全部 Clip 已可达。
- 协议版本 1：Attach 建立 editor session；Context/ContextReady 使用 generation；Selection 带递增版本、稳定 noteIDs 和交互就绪状态；Native 工具等待页面可交互。React 侧同时核对实际选区和活动手势，迟到命令拒绝。Attach 完成前的刷新等待同一初始化请求，避免早期事件安装空 session。
- Submit 冻结工程、轨道、片段、revision 和客户端 opID；只接受所选片段的 note.add/update/remove、可选长度修改，以及共享撤销/重做。拒绝其他容器、额外载荷、错 session/generation/revision/目标。核心变换编译器省略 trackId，桥接返回时补入已核实的所选轨道；Submit 不放宽目标校验。
- WebView 提交共用 Native Edits 协调层，代理现有 app.Service。事务已保存后仍保留原 pending-project-edit，直到页面 Acknowledge 再核对权威结果并清除。页面重载、确认失败或回复未知走原结果查询，不自动重放，也不把本地查询无结果误当远程操作已失败。
- 普通卷帘工具栏为 Native：翻页、选区、复制/删除、固定 1/16 量化、正负半音移调。原有力度表单、量化单位选择、缩放/吸附等普通工具尚未全部迁移，不能退役旧工具栏全部能力。
- Native 播放/停止调用原 app.Service/FluidSynth 管理器，后台查询状态供显示，不用 UI 时钟调度声音。本批未实测出声、seek/loop、音频设置或播放负载；这些仍需迁移/验收。
- 关闭统一拦截窗口与 App 退出，冻结 Native 命令及页面 inert；异步收集现有卷帘手势/草稿/提交 blockers，2 秒无响应显示未知。确认前复核状态版本与页面快照，返回时解除冻结；已在途提交的确认仍允许完成。未迁入的 Native 表单与 Agent 草稿不得被视作已覆盖。

- `TestMyGoNativeReadOnlyProject`：读取、Native 片段切换、typed event、实际 GridSound DOM 替换、清洁关闭通过；重开查询整个工程/CC/revision 相同。

- 新增应用数据目录下 `native-conversation-drafts.json`，只属于 Native 输入，不读取或改写旧浏览器 localStorage/IndexedDB。版本 1 的 `entries` 按对话 ID/`new` 索引，包含 token、原文、原始 uploads、dispatching 和已确认 runID；全部文件上限 64 MiB，原文上限 10000 字节。应用服务串行 CAS、私有临时文件、fsync/rename/目录同步；空条目保留 token 防迟到写复活。损坏/未知版本/符号链接拒绝并保留原文件。草稿是 UI 恢复数据，不是工程格式或数据库迁移。
- 输入写入与既有音乐草稿复用桌面串行队列，但保存接口只更新指定对话条目；冲突或写入失败保留当前输入并显示独立错误，不能把历史刷新成功当作保存成功。被删除对话的未发送输入仍保留，并可在对话选择器的“保留输入”条目读取；不会因删对话删音乐。
- 发送前用原 `PreviewSend` 展示真实远端地址、材料范围及敏感内容提示，只有点击确认后才为缺失范围调用原 `GrantExfil`，合并已有范围；权限不是 blanket grant。调用前重查对话绑定/配置身份和端点预览，变化要求重新确认；后端权限、运行冻结配置与实时限制仍是权威。外发授权属于原会话权限上下文，审批、撤销设置和全部远端变化场景仍待完整验收。
- 新增 `StartConversationTaskForProject` 桌面门面：显式接收确认时的预期工程绑定（空字符串表示普通聊天），与原 `SetConversationProject` 共用绑定锁，校验并冻结后才调用既有任务启动逻辑。原入口也经同一锁；存储事务的范围校验仍保留。这是为 Native 确认接线增加的目标保护，不替换调度器、Agent 循环、角色或执行配置。
- 调用任务服务前先持久保存 dispatching 标记；收到成功 runID 后才消费输入。调用报错或退出中断保留输入与待核对状态，要求查看原消息/任务后显式解锁，不自动重放。消费写入失败也不能称未发送。关闭协调计入草稿、保存/读取失败、在途附件/发送及待核对标记；独立历史刷新不会清除发送失败提示。
