# P2 MIDI 编辑界面：第一批实现契约

更新：2026-10-17。本文约束 P2 的第一批编辑界面，接续 [P1 工程事务](p1-project-model.md)。随后已实现的播放/原生音频/音色以 [P2 播放契约](p2-playback.md)为准，取代本批原先的试听占位；起始点表单与固定尺的展示已由 [时间图契约](p2-time-map.md)替换；轨道/片段列表的展示在 2026-10-18 由[编排画布](p2-arrangement.md)替换，原管理能力保留，具体入口及手势语义以该增量契约为准。P2 整体及原生窗口/真实设备完整验收仍未完成。

## 范围与接线

- KEEP：现有工程/历史、三入口事务、控制及原始事件、对话、执行内核和扩展授权。
- REPLACE：工作区的编辑占位内容由轨道/片段列表和钢琴卷帘替代；本批原有试听占位已由后续播放批次的传输栏替代。
- ADD：固定版本 GridSound 的受控源码子集及许可说明、React 适配、范围分页、编辑工具栏、提交后工程通知。无 schema 或旧格式兼容改动。
- 所有编辑通过现有 `ProjectService.SubmitProjectOps`，撤销/重做通过现有服务；不另建前端权威状态、音乐撤销栈或 MIDI 重写通道。控制/原始事件不在本批提供编辑器，保留并显示数量；改音符不能丢掉这些事件。

## 时间、手势与冲突

- GridSound 的一单位是一个四分音符，映射为工程 PPQ tick；小数转 tick 使用正域四舍五入，时长至少 1 tick。音符网格与吸附保持均匀四分音符坐标；宿主小节尺另外按时间图契约显示实际变拍与工程绝对位置，不用上游固定尺冒充小节。片段起点为工程绝对 tick，音符位置仍是片段局部 tick。
- 钢琴卷帘一次展示 16 个四分音符的页面（可翻页）；只挂载 onset 在当前页的音符，尾部可延伸到下一页。前页开始的持续音在其起始页编辑，不在后页生成副本。缩放不改变时间值。全部 MIDI 音高 0–127 可滚动访问。
- 指针按下时冻结工程 ID、修订、轨道、片段及音符快照；指针松开整组提交。后来的选区或后端通知不重定向手势，不在松开时用最新修订重算意图。冲突拒绝后刷新权威状态并给出可操作提示，不自动重试或 rebase。
- 后端更新在非手势期间刷新视图；手势期间保留预览，结束后再协调最新状态。编辑请求期间禁用新编辑。指针取消、Escape、窗口失焦、切换片段或卸载取消临时手势，清理全局监听，不提交半成品。
- 添加/移动/拉伸/复制音符若延伸超过片段长度，同一原子事务先延长片段；负位置、越界音高等拒绝整组，不逐音符夹取造成不一致。
- 选择是临时 UI 状态，不写工程历史。Shift 点击/框选、全选、取消选择、删除、复制、方向键移动及宿主撤销/重做可用。输入框和输入法组合输入不触发编辑快捷键。
- 力度使用 MIDI 整数 1–127；屏蔽上游合成器 gain/pan/filter/LFO 编辑，使用宿主力度输入，不把增益当作 MIDI 力度。

## 轨道、片段与保存

轨道新增、名称、静音/独奏、新音符默认 MIDI 通道和程序号使用已有操作（导入音符保留逐音符通道，不批量改写原通道）；片段新增、选择、名称、起点/长度调整与删除使用已有操作。长度收缩仍由 P1 验证，不能截掉已有事件。后续时间图批次已提供速度/拍号全点编辑，替代首点专用表单。删除轨道/片段先说明影响并用应用对话框确认，可用共享撤销恢复。

工程列表与详情请求须防止迟到响应覆盖后来选择，刷新不能让旧工程暂时冒充新工程。编辑开始前冻结对象与修订；对话框等待时也不能重定向。成功提交即持久化，界面显示保存状态；刷新失败不把已提交编辑报告成未提交。请求结果不明时保留 opID，允许查询真实结果，不盲目生成新 ID 重试。

2026-10-18 补正了工程名称投影与依赖批量逆操作的 P1 缺陷：重命名后的列表/详情与状态同名，跨片段边界拉伸可整组撤销/重做；界面仍使用原服务，无本地补丁。具体语义及既有历史限制见 [P1 §8](p1-project-model.md#8-2026-10-18-名称持久化与依赖批量撤销修正范围)，验证见[增量记录](validation/p2-project-history-2026-10-18.json)。

同日另修正服务分配 ID 的历史保存：四类新增对象的重做复用原 ID，后续依赖这些 ID 的编辑可沿共享历史撤销/重做。浏览器新增 10 项、累计 97 项检查通过；不要求前端提前分配 ID，也不改写旧缺省 ID 历史。范围与证据见 [P1 §9](p1-project-model.md#9-服务分配-id-的重做稳定性修正)及[验证记录](validation/p2-stable-ids-2026-10-18.json)。

后续的 [P1 §10](p1-project-model.md#10-工程生命周期内的对象-id-防复用)补齐普通新建的历史 ID 防复用，不改变正常 GUI 自动分配 ID 的方式。浏览器再新增 5 项、累计 102 项：实际选择并删除音符后，普通请求复用原 ID 或携带内部恢复载荷被拒绝；拒绝不发布修改，原对象仍可经界面撤销/重做恢复。见[本批记录](validation/p2-identity-reuse-2026-10-18.json)；不代表原生 WebView 或历史极端规模验收。

## 性能与验证

本批诊断目标：本机 Linux Chromium，记录浏览器/CPU 及 viewport；1k/10k 源音符均用分页投影，记录挂载/翻页/编辑命令耗时及实际挂载数量。首屏同步挂载目标 <200ms（1k）、<500ms（10k），不等于帧率或 Wails WebView 指标；密集同页最坏情况仍须披露。超目标先测量再调整，不以隐藏数据冒充通过。

验证：真实鼠标新增/拖动/拉伸；多选整组提交、力度/复制/删除及共享撤销重做；后台修改发生于拖动期间时拒绝旧修订；更新事件刷新、迟到请求不串工程、取消/卸载不提交；导入控制/原始事件在音符操作后保留。浏览器测试若使用模拟 Wails 门面只证明前端交互，真实后端事务另由 Go 集成测试验证。构建不替代原生窗口、听感或音频时序验收。


## 提交通知与结果恢复

应用服务在新建、导入、编辑、撤销/重做成功后发送 `project.changed`（projectId/revision），删除后发送 `project.deleted`；GUI/CLI/Agent 共享该路径。通知可能重复/迟到，只触发查询，不作为另一份状态。被拒绝的事务不发送变更通知。

2026-10-18 的[提交恢复增量](p2-operation-recovery.md)替换本节原来的 sessionStorage 标记。GUI edit/undo/redo 在发音乐命令前等待 Go 持久记录原工程/opID 成功；重开先读记录再启用编辑，未知结果继续阻止新编辑并提供查询。提交结果和恢复标记清理分开报告，清理失败不抹掉“已保存”结论。查无结果不自动判定失败，可继续等待，或用户确认任务结束后刷新并停止等待。原操作不会自动重放；损坏或未知版本文件明确报错并保留。未应用表单、指针预览与真实原生崩溃验收不包含在此提交恢复批次内。随后[时间图草稿增量](p2-time-map-drafts.md)只接续速度/拍号表单的持久检查点与显式恢复；其他输入仍待完成。

## 当前验证记录

`go test ./internal/...`：当前后端回归；`TestProjectNotificationsArePostCommit` 验证通知只发生于提交后且冲突不发通知；`TestProjectNoteEditsPreserveOtherEvents` 验证修改/撤销/重做保留控制与原始事件。

浏览器到真实服务的可复现入口：`env ICETUDIO_MUSIC_BROWSER=1 go test ./internal/app -run '^TestMusicEditorBrowser$' -count=1 -v`。测试在 `.cache/browser/music/run-*` 留存隔离数据库、浏览器日志、results.json 和截图，通过临时测试桥调用真实服务；它不使用 Wails 原生桥或音频。页面以 React StrictMode 挂载，包含实际鼠标、选择/键盘、外部冲突、取消、卸载重挂、结果查询与迟到响应隔离。原有 `node frontend/e2e/product.mjs` 继续覆盖对话/设置/权限产品路径，使用模拟后端，与本测试的结论分开。

已验证环境为 Linux、AMD Ryzen 7 7735H、Chromium 154、1440×1000。1k/10k 分散音符的当前页均挂载 64 个音符；第一批计时样本的投影同步更新约 10–15ms，服务提交与刷新约 120–200ms。后续播放批次的计时见其单独记录，不把这些区间作为性能保证。翻页测试总时长包含脚本轮询/等待，不能当作纯渲染时延或帧率。结果来自本机样本，不覆盖同页密集 10k、其他硬件或 WebView；性能计划条目仍保持未完成。

第一批浏览器运行的 19 项结果与原始计时保存在[编辑验证快照](validation/p2-editor-2026-10-17.json)；后续新增模拟音频门面的传输栏检查，与真实原生音频测试分开记录在[播放验证记录](validation/p2-playback-2026-10-17.json)。其中时长是对应样本而非跨环境保证。
