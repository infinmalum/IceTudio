# P2 GUI 工程提交的持久恢复

状态：2026-10-18，实施前建立、现已完成下述限定代码与验证的有效增量契约。接续 [编辑事务](p1-project-model.md)、[编辑界面](p2-midi-editor.md)及[退出保护](p2-close-guard.md)。本批只覆盖 GUI edit/undo/redo 的待确认操作，不覆盖未应用表单、指针预览、文件导入导出或任意外部副作用的恢复。

## 层级与顺序

- REPLACE：useProjects 的 sessionStorage 单条待确认标记，改为 Go 应用数据目录的 `pending-project-edit.json`（版本 1）。不读取或迁移旧标记，无数据库格式修改。
- ADD：app.Service/Wails 的读标记、开始记录、按原工程/操作 ID 清除接口；本机恢复门面，不增加 Agent 工具或 CLI/IPC 入口，不授予音乐编辑或外发权限。
- KEEP：GUI/CLI/Agent 统一事务、基础修订检查、opID 去重、整组提交、撤销、项目独立保存、运行内核和授权链路；恢复记录不是权威音乐状态，不存可重放的操作集。

沿用宿主独占数据目录锁（AcquireHostLock）；互斥保证以单个持锁宿主内一个 Service 为前提，不支持多个独立 Service 绕过宿主锁并发写同一目录。单个应用数据目录同时只允许一个 GUI 待确认操作。记录包含工程 ID、原 opID、冻结基础修订、操作种类和工程名称。Go 方法用工程恢复互斥锁串行读改写（后续时间图草稿同用该锁），支持同 ID/同意图开始请求幂等；不同未清除标记拒绝覆盖。同 ID 改变基础修订或种类也拒绝。文件采用同目录临时文件、文件 Sync、原子 rename 和目录 Sync；清除按工程+opID 比对，只删除匹配标记并同步目录。文件缺失表示无标记；截断/非法/未知版本/过大记录必须明确拒绝且保留文件，不能按空状态覆盖。

编辑发送顺序：先在前端设置同步锁和原 opID，再等待 Go 持久标记成功，才调用既有 Submit/Undo/Redo。开始记录失败不发送音乐命令；若应答丢失，仍保留该 opID 并允许查询，因为持久化可能已完成。提交成功后才清除原标记；清除失败不把已提交修改报告为未提交，保留恢复入口。明确方法拒绝并确认原结果不存在，可清除标记；单独“查无结果”不能证明请求失败或已结束。

启动时先读 Go 标记，读取完成前禁用工程操作，并注册退出阻拦。读取失败显示明确错误与“重试恢复检查”，不静默启用编辑；只允许继续读取/诊断。读到标记后不自动执行任何音乐命令，用户可“查询保存结果”。找到结果则先展示已保存并刷新，再尝试清除原标记；视图刷新失败也不改变已提交结论；查不到则保留未知，可继续等待，或用户明确确认原任务已结束后刷新并停止等待。查不到结果或读文件失败都不等于操作失败。

已有标记即使工程被删除仍保留；查询无结果时由用户明确停止等待，工程列表确认该工程不存在后可清除原标记，不要求重建工程。不按当前选择的工程替换恢复目标。持久文件只属于当前应用数据目录，不能清理其他目录或共享服务。

## 验证与限制

Go 测试覆盖重建 Service 后读取、提交与未提交记录、同意图幂等/不同意图冲突、并发开始/清除、损坏/未知版本保留、文件系统路径错误、过期清除、工程删除和音乐数据未被记录动作改动。浏览器验证前置记录失败不提交、提交后清除失败保留真实结果、清空浏览器会话存储后 reload 仍能查询同一 opID、启动读取失败时编辑/退出被阻拦、无结果显式停止等待。

浏览器仍经测试桥调用真实 Go/SQLite；桌面退出与音频门面模拟。重建 Service/页面 reload 证明相应恢复路径，不证明真实 Wails 进程崩溃、断电或所有平台文件系统语义。本批不含未应用输入的恢复；后续[时间图草稿增量](p2-time-map-drafts.md)接入该表单的检查点/重开恢复，数字字段/力度/播放参数等其他输入仍待实现，不把任一批次扩写为完整崩溃恢复验收。
