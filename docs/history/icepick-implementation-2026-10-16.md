## 1. 目标与交付边界

用户以 Profile 定义完整场景，选择内置 main、planner、worker、reviewer、improver 执行组件。宿主自动创建运行实例，统一执行流程、持久化、权限、审批和预算。桌面与 CLI 不再要求用户维护持久 Agent 列表。

按实际能力分批提供日常助手、研究分析、写作编辑、开发协作四个经过验收的场景 Profile，以及空白创建入口。Profile 可选择直接执行、动态规划或固定流程，按需组合组件；审查和复盘在当前场景内调用，不要求切换 Profile。配置改进可创建和修改 Profile/Skills，使用独立草案、评估、版本发布与回退。

新核心入口先交付 R1–R2 的配置契约、直接执行和日常助手；后续能力逐阶段增加。不能为了“一次完成全部新架构”拖延可用核心，也不能把未实现的组件开关作为已交付能力。通用插件加载器、任意脚本工作流、图数据库、Jev、A2A、持续任务不作为此次基础重构前置条件。

当前范围决策：参考 Pi 的最小基础工具路线，内置操作能力收敛为读取、写入、精确编辑和命令执行。下一实现优先补齐这四类能力；保留已实现的组件协作与状态工具，按 Profile/组件需要提供。Skills 承载场景方法，MCP 承载外部能力，不为各类业务新增专用工具，也不扩展持续/定时或嵌套调度。命令执行不承诺通过简单命令白名单实现文件系统或网络沙箱。
