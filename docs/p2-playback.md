# P2 原生播放与试听契约

更新：2026-10-24。接续 [编辑界面](p2-midi-editor.md)。本文为实现前建立并随代码同步的有效契约；初次播放接入的历史验收见 [2026-10-17 记录](validation/p2-playback-2026-10-17.json)，持音踏板/音色追溯增量见 [2026-10-18 记录](validation/p2-chase-2026-10-18.json)，RPN/NRPN 与单音/连奏/滑音追溯验证见 [2026-10-24 记录](validation/p2-ordered-controllers-2026-10-24.json)。各记录只覆盖各自范围，不扩大其他测试。P2 整体尚未通过验收。

## 范围与架构

ADD：`internal/playback` 的时间映射、不可变播放快照、原生 FluidSynth 渲染与传输服务；Wails 播放门面、工作区传输栏、程序生成的基础音色。KEEP：全部现有工程事务、历史、授权、Agent 机制及导入导出。无 schema 变化。播放状态是应用运行态，不写音乐撤销栈；模型不参与播放。

Linux+cgo 使用系统动态 libfluidsynth，开发验证版本 2.6.1（LGPL-2.1-or-later）。编译需要标准 include/library 路径中的开发头文件及动态库；其他尚不支持的平台在音频门面返回明确原因，不用浏览器音频或隐式降级冒充原生播放。音频初始化失败不阻止编辑，但不是整个应用的跨平台支持保证；现有 SQLite 驱动需要 cgo，因此 CGO=0 的播放包测试通过不能证明完整编辑器可运行。发行包的库/依赖与许可收集仍须 P5 验收。

Go 在音频线程外查询工程、校验并构建按帧排序的只读事件数组。原生音频回调独立推进采样帧，调用 FluidSynth 渲染；不调用 Go、数据库、模型、文件 I/O 或 React。控制线程交换已构建的数组；回调使用 try-lock，争用时输出零并计数，不等待 UI。该计数可诊断，不能冒充已测物理声卡时延。

## 时间和事件

- 固定 48 kHz、立体声、建议 period-size 128 / periods 3（缓冲目标约 8ms，实际设备/服务端可能不同）；目标命令生效 <50ms，实际物理输出延迟与高负载表现须实测。
- 速度图分段积分将 tick 转为秒，再四舍五入到采样帧；逆映射用于显示播放位置，拍号不改变时长。片段局部事件加片段起点。
- 仅播放未静音轨；存在独奏时仅播放未静音的独奏轨。内部按（轨序号×16 + 原通道）隔离通道（FluidSynth 单实例上限 256，使用四个独立实例支持全部 64 轨×16 通道；外部音色因此最多载入四份），使不同轨的程序、控制器、静音互不污染。音乐数据和导出的原始通道不变。
- 支持 note on/off、CC（含 64 踏板、120/123 停音、121 重置）、program、bend、channel/poly pressure。元信息仅参与时间映射，SysEx/未知原始事件保留在工程且不执行；显示跳过数量。原始无配对 note-off 也不直接执行，避免影响其他音符。
- 同帧保持稳定顺序；note-off 先于 note-on。同通道同音高重叠使用最近触发的音符，过期 off 不关闭后来触发者；该试听策略不改写存储。
- 工程末端为片段/音符/事件的最大结束位置，额外留 0.25s 释放尾音；结束时清踏板与声音并停止。不执行任意 SysEx。

## 传输与更改

- Play 冻结工程 ID/修订并读取权威状态；界面携带预期修订，过期播放请求拒绝并提示刷新。开始位置限在工程内。Stop 保留当前位置并清理声音；回到开头显式 seek 0。再次 Play 在该位置重建延音/控制器状态。
- Seek/循环使用半开 tick 区间；循环 A<B 且不得超过工程末端。Play 在读取工程前检查 ID、负位置和循环次序；编译得到工程末端后再检查上限，安装前检查循环至少一个采样帧。Seek 复用已载入的快照检查全部范围。每次跳转/循环边界先清掉旧声音/踏板，再重建目标点之前的控制器、程序、弯音及跨越该位置的持续音，包括踏板保持的音符；不重放任意外部副作用。
- 编辑、撤销或重做提交后，独立后台工作接收更新提示，读取新工程并离线编译。切换时保留实际音乐 tick，清理旧声音并重建该位置状态，在受控块边界安装新快照；不会因 React 卡顿或模型调用暂停事件推进。编译/读取失败保留旧快照并显示错误及实际播放修订；不声称新修订已应用。
- 新播放/停止/配置变更和后台编译之间使用序号校验：过期编译不得恢复已停止的播放或重定向另一个工程。首次 Play 安装后重新查询，补上安装前可能错过的提交提示。工程删除停止对应播放并取消尚未完成的同工程 Play；切换工作区显式停止原工程，卸载/迟到请求使用按工程限定的 Stop，不得停止后来另一个工程的播放。应用退出销毁 driver 后再销毁 synth。
- 音频设备初始化失败明确报错；音频配置不阻止无模型编辑。失去回调时报告设备无进展并提示重新初始化，保留工程和编辑历史。运行态不自动跨重启恢复播放。

位置输入以“定位”按钮或 Enter 应用，进度滑条在松开时定位；停止后定位不自动播放。循环输入以“应用循环”或下一次 Play 应用；初始化/重连或成功切换音色停止旧引擎，须再次 Play。控制栏中的状态轮询仅用于显示，不能驱动音频调度。

开启循环时，首轮允许从 A 之前开始，到 B 后跳回 A；请求开始位置达到或超过 B 时从 A 开始。循环边界重建的是离散音符/控制状态，包络和控制器的恢复限制见下文。

## 持音踏板与音色选择追溯（2026-10-18 增量）

本增量 ADD：CC66 持音状态追溯；REPLACE：按控制器编号排列的音色选择恢复，改为先恢复最后一次 Program 时的 bank，再发 Program，最后恢复尚未触发 Program 的 bank。KEEP：工程事件、实时派发顺序、全部入口、权限、事务与多 Agent 内核；无存储/API 变更。

追溯仅处理目标采样帧**之前**的事件，目标帧事件仍由原生调度器执行一次。CC66 ≥64 捕获当时仍存在的音符（包括 CC64 保持音）；重复收到 ≥64 也重新捕获，匹配 FluidSynth 2.6.1。之后触发的音符不因已有 CC66 自动被捕获。note-off 后任一保持条件有效就保留；CC64/66 各自释放不取消另一踏板的保持。CC120 立即清音，CC123 作为所有当前键释放、遵守踏板，CC121 释放两个踏板并清除捕获，但不释放仍按住的键。

跳转/循环/修订切换使用同一预计算追溯序列：先普通控制与 bank/program，再被 CC66 捕获的 note-on、CC66、未被捕获的 note-on，最后对已松键者发 note-off。全部分析在 Go 控制路径完成；回调只执行压缩后的序列，不扫描历史。CC66 释放后仍按住的音符不会遗留捕获标志。每通道 bank/program 恢复最多五条事件，踏板/音符恢复量由目标点存活音符数量决定，不随之前的踏板次数增长。

清理旧状态时先复位控制器/踏板，最后发 all-sounds-off；源码显示两者都会排入声音更新；结合对照测试，推断原顺序让踏板释放覆盖先前的 voice-off。修订切换测试曾检出 64 帧之后仍有旧音衰减，调整顺序后该测试剩余 1984 帧能量为 0。最初最多 64 帧仍可包含内部已生成的旧 PCM；这一样例不证明任意设备、音色或负载下的声音切换时延。

边界：沿用当前同通道/音高的最新触发追溯策略；不恢复旧包络、释放尾音或旧的同音高声音层。RPN/NRPN 与单音/连奏/滑音的有序追溯已于 2026-10-24 完成验证（见下节与[验证记录](validation/p2-ordered-controllers-2026-10-24.json)），其边界如下节声明；不据此宣称任意 MIDI 的定位/循环声学无损。已覆盖双踏板交错、重复 CC66、CC120/121/123、目标帧边界、通道隔离、实际 FluidSynth PCM 与 bank/program 状态、循环、修订更新及停止，测试与限制见本次验证记录。引擎行为依据固定版本源码 [CC/Program 处理](https://github.com/FluidSynth/fluidsynth/blob/v2.6.1/src/synth/fluid_synth.c)、[控制器复位](https://github.com/FluidSynth/fluidsynth/blob/v2.6.1/src/synth/fluid_chan.c)与[声音释放](https://github.com/FluidSynth/fluidsynth/blob/v2.6.1/src/synth/fluid_voice.c)，不以最新文档推定所有版本行为。

## RPN/NRPN 与单音/连奏/滑音有序追溯（2026-10-24 验证）

实现随 2026-10-23 代码批次提交，本日按 P2 收尾清单第 1 项完成验证与边界声明；产品代码无改动。ADD：验证证据与边界。KEEP：工程事件、实时派发顺序、全部入口、权限、事务与多 Agent 内核；无存储/API 变更。

- **RPN/NRPN**：编译期 `resolveParameters` 按本机 FluidSynth 2.6.1 的选择器协议（CC98/99/100/101 + 数据录入 CC6/38，含 GS NRPN→普通控制器、SF2 NRPN 生成器、通道 NRPN、CC121 对选择器与已生效值的区分）把事件流解析为自包含 Parameter 事件；选择器状态只存在于编译器，音频回调与重建的引擎不携带隐藏选择器。追溯按寄存器去重，一条受影响寄存器一个值；RPN 调音组用其历史 tuning bank 恢复。已证：连续播放参考与定位/循环后引擎寄存器值一致、10 万次数据录入压缩为有界 chase、通道隔离、停止后无泄漏、定位后的后续数据录入按原始流解析。
- **单音/连奏/滑音**：CC126/127 通道模式按 124/126 折叠追踪并先于音符恢复；CC68 连奏脚印、CC5 滑音时长、CC65 开关与 CC84 源音高在 chase 输出中按使用次序排列（CC84 先于使用它的 note-on，且被后续 note-on 消费后不再重现）。已证真实 PCM：定位到滑音目标 onset 与连续播放的滑音轨迹一致；mono+CC68 经 ≥2 次循环回卷仍单音；mono 之后的安装恢复复音；跨轨隔离。
- **彻底清理**：安装/停止/循环回卷/播放中修订切换共用 clear()——复位 portamento time mode、pitch wheel sens、RPN 选择器与调音、basic channel（回 OMNIOFF_POLY）、CC5/64/65/68、bank、弯音，最后 all-sounds-off。已证：播放中修订切换把弯音范围 12/CC65/CC68/+12 半音弯音全部清除，持续音符回到自然音高且播放不中断。
- **边界（不承诺声学波形完全相等）**：重触发音符包络从 attack 重新开始；不恢复原释放尾音与旧同音高声音层；目标点已在滑音中的音符按目标音高重放（滑音相位不保留），定位点之后的滑音从源音高完整复现；mono/legato 追溯按原始触发次序重放，最后一个音符胜出，连奏包络衔接不保证一致。等价性证据来自内置基础音色的离线 PCM 构造用例，不外推到任意 MIDI、任意音色或任意负载；原生窗口与物理设备仍属收尾清单第 4/5 项。

## 音色与配置

自带音色由仓库生成器从正弦/三角/锯齿/方波公式生成，不含录音、第三方采样或 GridSound assets。它是基础合成器试听，不标为 General MIDI 拟真乐器。128 程序分成四组波形；打击通道也采用基础波形。生成数据使用 CC0-1.0，生成代码沿项目许可；许可说明随源码提供。

用户可以通过原生文件选择指定 SF2/SF3；使用外部音色不代表项目已核实该文件授权，也不复制进工程/分享包。只接受 12 字节至 512MiB 的普通文件及大小写无关的 SF2/SF3 后缀，交给 FluidSynth 载入；失败保留原可用配置。此上限不是对任意恶意 SoundFont 的安全证明。驱动配置提供明确选项，连接失败不静默改用另一个引擎。`audio.json` 当前为版本 2（音色列表、默认与优先级，语义见[工作区与音色链契约](p2-daw-workspace.md)）；不支持的版本明确拒绝并保留文件，不自动覆盖。

## 验证与门槛

- Go 测试精确覆盖速度变更、tick/frame 逆映射、静音/独奏与通道隔离、同音高重叠、控制器/持续音追溯、循环边界、停止/跳转/编辑切换及资源清理。
- 使用真实 FluidSynth 离线渲染并检查 PCM 非零、音高/时长、停止清音和多轨程序；不把模拟 synth 或事件数组断言当作实际渲染。
- 可选真实 PulseAudio driver 测试验证回调进展、停止及 app 编辑/撤销更新；循环边界由真实引擎的离线渲染测试覆盖。两者都不等于人工听音或物理往返延迟。
- 浏览器验证传输按钮接线、错误提示与编辑功能回归；真实 Wails/WebKit 窗口的播放、停止与试听已于 2026-10-24 验收（见[原生验证记录](validation/p2-native-final-2026-10-24.json)）；设备切换/失联、高负载/xrun、干净系统安装及音乐质量仍需明确记录，不凭构建勾选全部 P2。

FluidSynth 内部合成缓冲通常为 64 帧，事件实际发声允许这一内部量化误差（48kHz 时约 1.33ms）；采样帧调度不等于已测得端到端物理延迟。外部音色最多载入四份，512MiB 的单文件上限不代表低内存占用；大音色的资源/延迟表现仍待发行性能验收。许可记录见 [本批音频许可](../licenses/README.md)。

当前实现支持最多 64 轨、100 万个播放事件及 24 小时时长；每个 synth 的 polyphony 为 256，超出时由 FluidSynth 分配/抢占声音，不承诺所有重叠音符均完整发声。四实例混音没有响度归一化；多轨高密度信号可能过载，仍需后续电平控制与负载验收。CC/弯音等结构化控制参与播放；所有原始事件仅保留，播放时跳过。外部 SF2/SF3 文件选择接线已实现，但本批真实渲染测试只使用内置原创 SoundFont。

追溯当前按最新控制值、CC64/66 保持状态、上述 bank/program 顺序及 RPN/NRPN 与单音/连奏/滑音寄存器重建，重触发音符的包络从头开始；不承诺恢复原释放尾音、旧同音高声音层或进行中的滑音相位（边界见 2026-10-24 增量节）。相关事件在工程和实时顺序派发中保留；等价性以内置基础音色的构造用例证明，不能称为任意 MIDI 的无损试听。基础波形未实现抗混叠，极高音听感仍需评估。

2026-10-17 初次接入批次已验证 Linux+cgo 上真实 FluidSynth 2.6.1 的 PCM/A4 音高、四波形与高轨路由、踏板/控制器追溯、跳转/循环/停止；后台修订更新保留音乐 tick，Stop 可取消尚在读取中的 Play，失败更新保留旧快照。真实 PulseAudio 测试经本机 PipeWire 兼容服务推进回调，另验证 app 提交/撤销后的播放修订。浏览器 20 项检查复用真实 Go/SQLite 工程服务，传输栏使用明确的音频门面 mock；未验证真实 Wails WebView→原生音频的端到端路径。设备失联/切换、人工听音、物理延迟、干净系统安装和其他平台仍未验证；密集音符负载预算已于 2026-10-24 在浏览器套件强制并记录，原生窗口当前实现的复测随原生性能验收补做。
