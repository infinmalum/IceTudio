# E6 插件、音色与节点组合

2026-11-08 开始。本文记录 E6 的 Linux 产品实现、独立宿主实验和验收边界。范围和退出门槛以 [实施计划](implementation.md)、[功能矩阵](feature-matrix.md) 和 [验收矩阵](acceptance.md) 为准。

## 已接入的内置效果

在 Native「混音」工作区打开通道的「路由 / 效果 / 自动化」，在「效果类型」中添加新槽，调整参数后点击「应用」。四种效果复用已有排序、旁通、湿信号、命名预设、参数自动化和共同撤销。工程仍保存稳定效果 ID 及 0–1 的 `amount`、`wet`，MIDI 文件继续只交换 MIDI 内容。

| 效果 | 强度旋钮控制 |
|---|---|
| 立体声合唱 | 0.35 Hz 的调制深度，左右湿信号的反向延迟变化范围最大为 1–15 ms |
| 低通滤波 | 一阶滤波器的截止频率，归一化范围约 100 Hz 至 16 kHz |
| 软削波失真 | 非线性驱动量，零驱动为原信号 |
| 噪声门 | 立体声联动阈值。开关使用不同阈值，增益平滑过渡 |

这批新增效果不引入需要图补偿的延迟。合唱延迟属于湿信号，低通和合唱在自然结束时保留短尾音。混音运行及导出共用原生渲染路径。样本回归覆盖左右合唱延迟、一阶低通的高频衰减、驱动自动化的采样帧边界、噪声门闭合和四类旁通／零湿信号。音乐听感及实机长时负载仍待验收。

Linux 全量 Go 测试、`go vet`、生产构建和实际 MyGo 窗口回归通过。窗口回归覆盖既有混音草稿、提交、撤销、重做和 WAV 导出。四种新效果的 DSP 验证来自样本回归，尚未逐项手动操作和试听。

六个模块均报告 X11 嵌入可用、原生 Wayland 嵌入不可用，默认状态的插件延迟均为 0 帧。之后增加了三项实验。下表的边界是该次独立实验的范围，生产接线结果见「运行验证与剩余验收」。

| 实验 | 已验证的行为 | 验证边界 |
|---|---|---|
| 插件窗口 | 在隔离的虚拟 KWin/Xwayland 会话中，六个模块各两次挂载到宿主 X11 容器。打开后观察到可见子窗口，关闭后子窗口消失。CLAP 探针提供主线程 FD/定时器，VST3 探针通过 `IPlugFrame` 提供 `IRunLoop` | 验证打开、关闭和再次打开。真实桌面上的 MyGo 窗口集成、参数操作、缩放及原生 Wayland 仍待验证 |
| 动态延迟 | CLAP 与 VST3 各用自建测试插件发送重启／延迟变化通知。宿主停用再激活，报告延迟由 64 帧变为 192 帧，实测脉冲分别落在第 64 与第 192 帧 | 证明通知、重新激活和采样对齐。真实第三方非零延迟插件、跨路由延迟补偿及多插件链待测 |
| 跨进程缓冲 | Dexed 与 Surge XT Effects 的两种格式通过固定容量共享缓冲，单次 160 块，48 kHz／256 帧，输出固定晚 2 块。插件阻塞 36 ms 时，四组各错过并丢弃 5 块迟到音频，恢复后按序交付。两种 Dexed 的工作进程分别在第 48 块崩溃，模拟回调继续走完，后续 112 块输出静音 | 512 帧约 10.67 ms，属于传输预算。模拟回调队列操作 p99 为 1.4–2.1 µs，未计真实设备、图处理和插件计算。独立探针只传主立体声和样例音符。生产路由、离线导出和长时压力仍待测 |

共享缓冲由两条单生产者、单消费者队列组成，使用禁止缩小或扩大的匿名内存文件。插件工作进程仅收到该缓冲和测试输入，模拟回调以块序号判断截止时间，无需等待工作进程或访问文件。崩溃后的静音是这次实验的验证策略。生产运行使用下节分别定义的乐器静音、效果旁通和离线导出失败策略。

复验使用项目根目录的 Bash。前提是上述 SDK 分别位于 `bin/e6-deps/clap` 和 `bin/e6-deps/vst3sdk`，插件包解压至 `bin/e6-deps/dexed` 和 `bin/e6-deps/surge`。构建需要 CMake、Ninja、C++20 编译器和 X11 开发库。运行器需要启用了用户命名空间的 Linux、`bwrap`、`prlimit`、Python 3，以及本机测试所用的合并式 `/usr` 布局。`--editors` 另需 KWin、Xwayland、字体配置、XKB 和 D-Bus。执行时无依赖下载，矩阵通过会打印 `plugin probe matrix passed`。

```bash
cmake -S tests/plugin-probe -B bin/e6-deps/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCLAP_ROOT="$PWD/bin/e6-deps/clap" -DVST3_ROOT="$PWD/bin/e6-deps/vst3sdk"
cmake --build bin/e6-deps/build --target icetudio-plugin-probe scan-fault latency-fixture latency-vst3
python3 tests/plugin-probe/run.py bin/e6-deps --editors --transport --latency
```

## Linux 插件运行

1. 从「工程浏览器 → 音频插件库」扫描信任的本机目录。到「混音 → 路由 / 效果 / 自动化」选择目标通道。「通道」页加载插件乐器，「效果」页添加插入效果。选择后在隔离助手中读取初始状态。点击「应用」才提交工程。
2. 参数面板使用插件公开的归一化参数。可恢复上次捕获的状态值、为效果保存工程预设，或为任意乐器／效果参数绘制自动化。插件参数按处理块读取，支持曲线、触碰和锁定写入。内置推子与效果继续使用原有自动化。
3. 「打开插件编辑器」需要 Xephyr 和 X11/Xwayland。IceTudio 启动只供该插件使用的嵌套显示和随机认证信息。修改后回到 IceTudio 点击「获取插件窗口更改」，再点击「应用」。取消、关闭厂商窗口或修订冲突保留上次提交的状态。没有 Xephyr 时可继续使用 Native 参数面板。
4. 插件移动到其他目录后扫描新目录。相同格式、类 ID 与二进制 SHA-256 自动匹配。迁移到同类的新二进制版本需在原槽显式操作，并通过状态加载及参数 ID 检查。扫描失败、中断或用户停用的模块不会自动加载。项目载入本身不执行插件。
5. 「通道 → 渲染并冻结轨道」对已提交、带插件且没有外部侧链输入的轨道生成前推子缓存，包含一秒尾音。应用后，轨道直接播放缓存，原片段、效果、自动化和路由保留。冻结资产进入资源包；解冻后播放当前源片段和插件。冻结与解冻使用普通工程事务，可撤销。冻结期间，源片段和插件的后续编辑在解冻时生效。

实例按不可变播放快照分代。工程保存槽位 ID、格式、厂商、类 ID、版本、二进制摘要、状态及参数值。本机索引保存路径；便携工程内没有模块路径或可执行代码。每个实例最多 1 MiB 状态和 512 个公开参数，工程最多 16 个插件实例。插件的厂商窗口可呈现更多原生参数，参数曲线可用项取决于宿主登记的稳定 ID。

运行助手只访问只读系统库、审核过摘要的入口二进制及该 VST3 包资源。插件隔离使用 Bubblewrap 用户、网络、进程等命名空间及资源上限；正常播放没有桌面套接字，厂商窗口仅挂载嵌套显示的套接字和认证文件。入口摘要核对不涵盖 VST3 包内的其他资源或共享库，扫描前需信任整个包。

音频处理使用 48 kHz、256 帧块、主单声道或立体声总线。实时每个实例计 512 帧传输延迟，C 回调不等待助手。结果迟到时乐器静音，插入效果输出延迟对齐的干信号。离线每实例计一个 256 帧固定块的流水延迟，导出时裁掉总补偿等待；超时、缺失或运行错误中止发布。插件初始化时先确定延迟，实时运行遇到变化后最多重建两次快照，离线遇到处理期间的延迟变化中止本次导出。厂商插件的辅助音频总线、MIDI 输出和全部传输同步扩展未纳入此 Linux 接口。

## 内置音色与组合

「混音 → 音色」支持按名称或合成类别筛选、工程内收藏、试听、加载和调整音色与释放。内置音色使用生成波形，包括过滤锯齿、方波、FM 铃声和 Karplus–Strong 拨弦。内置音色和插件乐器均可作为轨道的 MIDI 音源。卸载后可恢复轨道原音源。

「混音 → 组合」显示所选通道的 MIDI 处理、音源、插入效果、推子和输出分支。移调和力度处理发生在播放编译时，工程原始 MIDI 保留。可把多个乐器／效果参数映射到一个宏，每个映射设置起点与终点。已写入的自动化曲线优先于宏设定的初值。命名组合预设保存处理链和宏，载入空通道时分配新槽位 ID 并重连宏。通道路由在「路由」页编辑，继续使用 E4 的有向图、反馈环拒绝及累积延迟补偿。

## Linux Native 插件库

从「工程浏览器 → 音频插件库」或「混音台 → 插件库」打开。选择信任的目录后点击「扫描所选目录」才会加载目录内的插件代码。列表可按名称、厂商、格式或路径筛选。失败、中断或需要刷新资源的条目可以单独重扫。批量扫描复用二进制 SHA-256 相同的登记结果，包含失败和中断记录。插件替换为不同二进制后可重新扫描。

- **ADD 桌面扫描与索引。** Native 入口通过 `app.Service` 调用扫描。每个模块在独立进程中加载，最长 6 秒。进程只获得扫描助手、只读模块、系统文件和临时目录，隔离网络及桌面会话。扫描支持 Linux 的常规 `.clap` 文件与标准 `.vst3` 目录包。发现过程不遍历符号链接或 VST3 包的内部目录。一次最多检查 128 个模块。
- **ADD 可重试的本机记录。** 在应用数据目录的 `audio-plugins.json` 记录模块路径、二进制 SHA-256、插件 ID、类型、版本和扫描结果。每个模块加载前先原子登记待完成状态。进程失败和超时保留诊断，正常取消保留之前已完成的模块，异常终止的检查点允许显式重试。隔离环境启动失败单独提示，避免把环境错误误写成插件故障。VST3 资源单独变化时使用单项「重新扫描」。
- **KEEP 工程与当前播放链路。** 索引只供本机扫描和运行解析使用，扫描不修改工程修订、历史或资源包。IPC 与 Agent 不开放扫描、加载、停用或厂商窗口控制入口。

扫描与运行助手是独立 Linux 二进制。SDK 沿用上节已核对的固定检出。已具备这些 SDK 和系统工具时，从项目根目录执行下面的命令。CMake 还需要 X11 开发库。扫描和运行依赖系统的 `/usr/bin/bwrap`、`/usr/bin/prlimit` 和可用的用户命名空间。

```bash
cmake -S internal/pluginhost/native -B bin/e6-deps/scanner-build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCLAP_ROOT="$PWD/bin/e6-deps/clap" -DVST3_ROOT="$PWD/bin/e6-deps/vst3sdk"
cmake --build bin/e6-deps/scanner-build --target icetudio-plugin-scan icetudio-plugin-run
install -m 755 bin/e6-deps/scanner-build/icetudio-plugin-scan bin/e6-deps/scanner-build/icetudio-plugin-run bin/
```

便携打包可以显式携带两个助手。用已有 SDK 构建时，可执行 `task linux:package:plugins ICETUDIO_CLAP_SDK="$PWD/bin/e6-deps/clap" ICETUDIO_VST3_SDK="$PWD/bin/e6-deps/vst3sdk"`。已有正式应用和两个助手时，可执行 `python3 scripts/package.py --os linux --binary bin/icetudio --plugin-helpers`。两个入口均不下载 SDK 或分发第三方插件。Deb、RPM、AppImage 和其他平台的插件交付仍由 E8 验收。

## 运行验证与剩余验收

- 六个真实模块通过生产助手的状态重开、定时驱动的非阻塞处理、WAV 导出、冻结后脱离插件渲染、进程退出和缺失插件不覆盖已有成品。CLAP 与 VST3 的延迟夹具在生产混音图内把两条路径的脉冲对齐到第 448 帧，其中 192 帧为插件延迟，256 帧为离线处理流水延迟。
- 生产厂商窗口助手在隔离 KWin/Xwayland 中通过六个模块的打开、状态捕获和重开。Dexed 的 Cutoff 在两种格式中均能捕获为 0.375。该验证使用虚拟显示，未覆盖正式 Xephyr 窗口的鼠标焦点、缩放、输入法和窗口管理。
- 实际 MyGo 回归在一次性工程中通过插件库扫描、Native 插件草稿持久保存、修订提交与 WAV 导出。Go 回归覆盖组合预设 ID 重连、宏的坏目标拒绝、冻结与音色状态的事务撤销、重做和便携快照重开。四种内置音色均验证试听和 WAV 产生非零 PCM。
- A08/A12 仍需真实音频设备长时负载、实际厂商窗口操作、第三方非零延迟实例，以及离线与设备播放的听感核对。Linux 混音图动态重建有回退边界，AU 与其他系统仍随 E8。

复测生产运行时，先完成上面的助手构建及独立延迟夹具构建，再从项目根目录执行 `go test -c -o bin/e6-playback.test ./internal/playback` 和 `env ICETUDIO_PLUGIN_RUNTIME_TEST="$PWD/bin/e6-deps" bin/e6-playback.test -test.run '^TestProductionPlugin' -test.v`。复测生产窗口状态捕获，准备上文虚拟显示依赖并执行 `python3 tests/plugin-probe/run.py bin/e6-deps --runtime-editors --latency`。
