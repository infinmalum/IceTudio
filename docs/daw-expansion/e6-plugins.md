# E6 插件、音色与节点组合

2026-11-08 开始。本文记录 E6 的 Linux 内置效果、独立插件宿主实验及后续接线条件。范围和退出门槛以 [实施计划](implementation.md)、[功能矩阵](feature-matrix.md) 和 [验收矩阵](acceptance.md) 为准。

## 已接入的内置效果

在 Native「混音」工作区打开通道的「路由 / 效果 / 自动化」，在「效果类型」中添加新槽，调整参数后点击「应用」。四种效果复用已有排序、旁通、湿信号、命名预设、参数自动化和共同撤销。工程仍保存稳定效果 ID 及 0–1 的 `amount`、`wet`，MIDI 文件继续只交换 MIDI 内容。

| 效果 | 强度旋钮控制 |
|---|---|
| 立体声合唱 | 0.35 Hz 的调制深度，左右湿信号的反向延迟变化范围最大为 1–15 ms |
| 低通滤波 | 一阶滤波器的截止频率，归一化范围约 100 Hz 至 16 kHz |
| 软削波失真 | 非线性驱动量，零驱动为原信号 |
| 噪声门 | 立体声联动阈值。开关使用不同阈值，增益平滑过渡 |

这批新增效果不引入需要图补偿的延迟。合唱延迟属于湿信号，低通和合唱在自然结束时保留短尾音。混音运行及导出共用原生渲染路径。样本回归覆盖左右合唱延迟、一阶低通的高频衰减、驱动自动化的采样帧边界、噪声门闭合和四类旁通／零湿信号。音乐听感及实机长时负载仍待验收。

Linux 全量 Go 测试、`go vet`、生产构建和实际 MyGo 窗口回归通过。窗口回归覆盖既有混音草稿、提交、撤销、重做和 WAV 导出。四种新效果的 DSP 验证来自样本回归，尚未逐项手动操作和试听。

## Linux 独立宿主实验

测试使用用户授权下载的 SDK 和插件，存放在项目持久测试目录 `bin/e6-deps`。CLAP 和 VST3 SDK 的固定版本带 MIT 许可。Dexed 包内附 GPLv3 文本。Surge XT 仅使用官方 1.3.4 的 Linux 纯插件包。探针与测试包独立于生产构建及安装包。 [CLAP](https://github.com/free-audio/clap/tree/1.2.10) · [VST3 SDK](https://github.com/steinbergmedia/vst3sdk/tree/v3.8.1_build_84) · [Surge XT](https://github.com/surge-synthesizer/releases-xt/releases/tag/1.3.4) · [Dexed](https://github.com/asb2m10/dexed/releases/tag/v1.1.0)

| 输入 | 固定版本与核对结果 |
|---|---|
| CLAP | 1.2.10，`195b42a004144fab0b3cf95e9c067187d15365b7` |
| VST3 SDK | 3.8.1 build 84，`3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96`。四个宿主所需子模块与该标签的固定提交一致 |
| Dexed Linux | 1.1.0，与官方 SHA-256 `3a1a01511e3428f432cc91c7bf5267d72bfcb68aded4f084d4f9d002dcc42da6` 一致 |
| Surge XT Linux | 1.3.4，纯插件包与发布方 MD5 `0180f06ec7a8445b1c749471e29c702b` 一致，本地 SHA-256 为 `dd431b75f5fa197c4bffa6ca27ca46970f0a94c834119bb1db7decdeec4c28db` |

2026-11-08，Linux 7.3.3-1-cachyos x86_64，GCC 16.2.1，Bubblewrap 0.13.1。探针以 48 kHz、256 帧逐块处理 MIDI 音符或测试信号。扫描、状态保存和状态重开各自在新进程执行。探针仅访问只读测试包和系统库及单次测试目录，没有用户目录、网络或显示会话。恢复阶段的状态文件以只读方式挂载。

| 插件 | CLAP / VST3 实测结果 |
|---|---|
| Dexed | 扫描、音符渲染、修改 Cutoff 后保存、重开恢复均通过。两种格式均恢复到 0.375，渲染信号统计与修改后的原实例一致 |
| Surge XT | 两种格式均发现 1 组音频输入与 3 组输出，音符渲染、状态保存和重开后渲染通过 |
| Surge XT Effects | 两种格式均发现 2 组输入与 1 组输出，音频渲染、状态保存和重开后渲染通过 |
| 故障 | 测试模块在扫描加载时注入崩溃。两种格式的 Dexed 在读取已保存状态并处理首块后，分别注入崩溃和超时。监督进程继续运行，重开恢复参数，保存文件的 SHA-256 未变化 |

六个模块均报告 X11 嵌入可用、原生 Wayland 嵌入不可用，默认状态的插件延迟均为 0 帧。之后增加了三项实验。

| 实验 | 已验证的行为 | 验证边界 |
|---|---|---|
| 插件窗口 | 在隔离的虚拟 KWin/Xwayland 会话中，六个模块各两次挂载到宿主 X11 容器。打开后观察到可见子窗口，关闭后子窗口消失。CLAP 探针提供主线程 FD/定时器，VST3 探针通过 `IPlugFrame` 提供 `IRunLoop` | 验证打开、关闭和再次打开。真实桌面上的 MyGo 窗口集成、参数操作、缩放及原生 Wayland 仍待验证 |
| 动态延迟 | CLAP 与 VST3 各用自建测试插件发送重启／延迟变化通知。宿主停用再激活，报告延迟由 64 帧变为 192 帧，实测脉冲分别落在第 64 与第 192 帧 | 证明通知、重新激活和采样对齐。真实第三方非零延迟插件、跨路由延迟补偿及多插件链待测 |
| 跨进程缓冲 | Dexed 与 Surge XT Effects 的两种格式通过固定容量共享缓冲，单次 160 块，48 kHz／256 帧，输出固定晚 2 块。插件阻塞 36 ms 时，四组各错过并丢弃 5 块迟到音频，恢复后按序交付。两种 Dexed 的工作进程分别在第 48 块崩溃，模拟回调继续走完，后续 112 块输出静音 | 512 帧约 10.67 ms，属于传输预算。模拟回调队列操作 p99 为 1.4–2.1 µs，未计真实设备、图处理和插件计算。独立探针只传主立体声和样例音符。生产路由、离线导出和长时压力仍待测 |

共享缓冲由两条单生产者、单消费者队列组成，使用禁止缩小或扩大的匿名内存文件。插件工作进程仅收到该缓冲和测试输入，模拟回调以块序号判断截止时间，无需等待工作进程或访问文件。崩溃后的静音是这次实验的验证策略。生产降级仍须区分乐器静音、效果旁通及离线导出失败。

复验使用项目根目录的 Bash。前提是上述 SDK 分别位于 `bin/e6-deps/clap` 和 `bin/e6-deps/vst3sdk`，插件包解压至 `bin/e6-deps/dexed` 和 `bin/e6-deps/surge`。构建需要 CMake、Ninja、C++20 编译器和 X11 开发库。运行器需要启用了用户命名空间的 Linux、`bwrap`、`prlimit`、Python 3，以及本机测试所用的合并式 `/usr` 布局。`--editors` 另需 KWin、Xwayland、字体配置、XKB 和 D-Bus。执行时无依赖下载，矩阵通过会打印 `plugin probe matrix passed`。

```bash
cmake -S tests/plugin-probe -B bin/e6-deps/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCLAP_ROOT="$PWD/bin/e6-deps/clap" -DVST3_ROOT="$PWD/bin/e6-deps/vst3sdk"
cmake --build bin/e6-deps/build --target icetudio-plugin-probe scan-fault latency-fixture latency-vst3
python3 tests/plugin-probe/run.py bin/e6-deps --editors --transport --latency
```

## 后续实施顺序与边界

1. **ADD Linux 生产宿主边界。** [Native 插件库](#linux-native-插件库)已接入后台扫描、扫描进程监督和本机索引。下一步实现运行实例监督。控制请求按实例及运行代际寻址，音频块按代际和序号验收。工作进程退出、超时或图换代时弃用该实例的输出，保留最后确认状态。先以独立 X11 容器作为编辑器候选，接产品前验证实际窗口焦点、缩放和关闭。待权限、包分发和窗口接线验证后冻结发布契约。
2. **ADD 工程与播放接线。** 复用 `app.Service` 的事务、修订、撤销和恢复，定义实例 ID、插件格式和身份、状态 blob 以及稳定参数 ID。机器本地模块路径与可携带工程分开保存。验证缺失或版本不匹配时保留槽位和完整状态，由用户选择重新定位。实时跨进程缓冲的等候策略和延迟先测量，回调只读取有界缓冲，禁止等候进程、文件或 IPC 锁。进程故障进入明确降级状态，离线遇到故障拒绝发布不完整成品。验证共享路由图补偿、自动化、实时与离线差异、冻结／解冻以及工程重开。窗口操作修改参数和状态仍经过工程提交。
3. **ADD 音色与组合。** 提供音色类别、预设检索、收藏、试听和宏参数。矩阵要求的减法、FM、物理建模分别留下可演奏、重开和导出证据。以 E4 音频图接入可视化音频／MIDI 节点、宏及组合预设，保留非法环拒绝和累计延迟补偿。组合支持的节点类型与可携带状态在该工作包实施前冻结。
4. **KEEP 原路径。** 保留 FluidSynth、采样器、内置混音、可携带工程、CLI/IPC、Agent 运行与权限边界。第一批只扩展既有 `mixer.set` 效果枚举和渲染行为。没有移除或替换工作入口，也没有冻结插件状态格式。AU 仍归 E8。

进程隔离首先用于故障恢复。允许执行哪些插件、进程继承哪些资源权限及怎样限制权限，需在启用第三方代码之前明确。扫描成功、单个插件正常或内置效果测试通过，均不能将 A08 动态延迟与 A12 插件矩阵标为通过。

## Linux Native 插件库

从「工程浏览器 → 音频插件库」或「混音台 → 插件库」打开。选择信任的目录后点击「扫描所选目录」才会加载目录内的插件代码。列表可按名称、厂商、格式或路径筛选。失败、中断或需要刷新资源的条目可以单独重扫。批量扫描复用二进制 SHA-256 相同的登记结果，包含失败和中断记录。插件替换为不同二进制后可重新扫描。

- **ADD 桌面扫描与索引。** Native 入口通过 `app.Service` 调用扫描。每个模块在独立进程中加载，最长 6 秒。进程只获得扫描助手、只读模块、系统文件和临时目录，隔离网络及桌面会话。扫描支持 Linux 的常规 `.clap` 文件与标准 `.vst3` 目录包。发现过程不遍历符号链接或 VST3 包的内部目录。一次最多检查 128 个模块。
- **ADD 可重试的本机记录。** 在应用数据目录的 `audio-plugins.json` 记录模块路径、二进制 SHA-256、插件 ID、类型、版本和扫描结果。每个模块加载前先原子登记待完成状态。进程失败和超时保留诊断，正常取消保留之前已完成的模块，异常终止的检查点允许显式重试。隔离环境启动失败单独提示，避免把环境错误误写成插件故障。VST3 资源单独变化时使用单项「重新扫描」。
- **KEEP 工程与当前播放链路。** 索引只供桌面使用，扫描不修改工程修订、历史或资源包。没有接入轨道、混音槽、插件编辑器或实时渲染。当前 CLI、IPC 和 Agent 未开放插件扫描权限。

扫描助手是单独构建的 Linux 二进制。SDK 沿用上节已获授权并核对的固定检出。本机已构建到 `bin/icetudio-plugin-scan`。首次安装从项目根目录运行以下 Bash 命令。正式便携打包暂未包含扫描助手。扫描依赖系统的 `/usr/bin/bwrap` 和 `/usr/bin/prlimit`，并要求用户命名空间可用。

```bash
cmake -S internal/pluginhost/native -B bin/e6-deps/scanner-build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCLAP_ROOT="$PWD/bin/e6-deps/clap" -DVST3_ROOT="$PWD/bin/e6-deps/vst3sdk"
cmake --build bin/e6-deps/scanner-build --target icetudio-plugin-scan
install -m 755 bin/e6-deps/scanner-build/icetudio-plugin-scan bin/icetudio-plugin-scan
```

本机全量 Go 测试、`go vet`、Linux 构建与实际 MyGo 窗口回归通过。窗口回归从插件库发起对 Dexed 目录的扫描，确认两种格式出现在列表，工程与修订保持一致。扫描助手集成测试另覆盖六个真实模块、扫描崩溃与 6 秒超时、跳过未变化故障、替换二进制后显式重试和索引重开。窗口回归直接调用目录选择后的操作，系统文件选择器的物理操作仍待走查。
