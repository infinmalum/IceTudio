# E4 混音图与自动化

2026-11-07。Linux 编码与下列自动化验证已完成。执行范围为 Linux Native 混音工作区、工程事务、FluidSynth/PCM 图渲染和自动化。E3 的实体设备验收单独追踪。

1. 先核对 FluidSynth 逐轨分离、输出等价性和 256 帧处理成本，再将输出接到统一图。四组各 16 轨，保留 64 轨及每轨 16 个 MIDI 通道。合成器设置与设备输出设置独立。
2. ADD 工程级混音快照。通道 ID 使用工程轨 ID、总线 ID 或固定 Master ID。效果用独立 ID，自动化目标用通道/效果 ID 和参数名。先验证引用、参数、上限和有向无环图，再提交带逆操作的修订。删除轨道、总线或效果时，同一事务整理失效引用并允许撤销。
3. ADD Native Mixer 的轨道条、主输出、总线、主路由、发送和压缩器侧链，接入电平与削波。配置有名称的内置效果、调整顺序和旁通。保留原生轨道 M/S 与编排联动。
4. ADD 混音参数曲线。曲线使用绝对音乐 tick，编译为采样帧，支持阶梯和线性。读取按当前音乐位置恢复。触碰模式仅在手势期间写入，锁定模式从首次调节持续至停止写入。一次写入作为一条编辑事务提交。支持直接编辑和复制曲线。
5. REPLACE 混音汇总的载体。在 Native 渲染线程应用已经编译的图，实时与离线共用处理。采用累计延迟和输入边对齐，离线去掉开头的补偿延迟。保留原有 MIDI 调度、控制器追赶、PCM、节拍器、试听和导出原子发布。无需在回调中调用 Go、读文件或申请图内存。
6. KEEP app.Service、Go 权威状态、CLI/IPC、共享历史和恢复、Agent 框架与授权范围。E4 混音编辑从 Native 与授权的项目命令入口提交，不向模型开放整图编辑。DELETE 无。

交付验证应包含持久化、撤销、拒绝环、逐轨 MIDI 分离、带延迟的并行脉冲、压缩侧链、自动化在定位和循环边界的取值及导出结果。记录 callback 开销和离线耗时，A09 的实机长跑单独记录。

## 操作与信号约定

- 在布局栏切换「混音」，可在编排下方查看轨道条。较矮窗口集中显示混音台。Master 固定在左侧，轨道和总线可横向滚动。轨道条显示颜色、输出、推子/声像读数、峰值、峰值保持、削波帧计数和插入槽。选中轨道或打开通道编辑器时同步当前编排选择。轨道 M/S 仍使用同一工程操作。
- 「路由 / 效果 / 自动化」打开当前通道草稿。添加总线可作为主输出、发送返回或侧链源。通道信号先经过插入链，再经过推子和立体声平衡。主输出和发送混入目标总线。侧链信号只进入目标压缩器的检测器，源轨仍可单独路由。所有边参加拓扑排序，禁止反馈环。未显式设置主输出的通道输出到 Master。
- 内置插入为固定 1 kHz 转折的倾斜 EQ、带外部检测的压缩器、64 帧预读限制器、50–500 ms 反馈延迟和三抽头立体声混响。效果槽支持强度、干湿比、旁通、重排和工程级命名预设。每通道最多 8 个效果，工程最多 128 个效果及 16 条总线。效果链实现为基础内置处理，插件宿主及插件参数由 E6 接入。
- 推子使用 0–2 的线性幅度，声像使用 −1–1 的立体声平衡，效果强度和湿信号使用 0–1。自动化曲线按稳定目标及绝对 tick 保存。首节点前使用面板值，最后一节点后保持，支持线性和阶梯。轨道和轨道插入的曲线在编排显示，可打开节点编辑。Master 和总线曲线在混音台中编辑。可点击曲线加点、按音乐位置精确编辑、删除或偏移复制节点。
- 实时写入前先播放当前工程修订，随后打开自动化编辑。触碰在推子接管期间采集，释放后恢复读取。锁定从首次移动持续到结束写入。循环回绕、定位到更早位置、快照修订变化或停播会结束本次写入。已采集点保留为草稿，点击「应用」后才进入工程共享历史。写入根据播放状态与 UI 手势采样，普通读取在采样帧上执行。
- 调度器仍按 48 kHz 渲染。分配快照时计算各支路累计延迟，音频与侧链都与该节点最慢输入对齐。循环跨界保留补偿和效果历史，定位或安装新快照从空效果历史开始。切换旁通、路由和修订会安装新快照，已有延迟/混响尾音从该点重建。实时自然结束保留估算的效果尾音，离线使用导出窗口明确指定的尾音并去掉开头的补偿帧。指定轨导出隔离其他源轨，保留所选轨的下游路由和效果。
- 无混音配置的工程按单位增益直通。播放快照保留四个 SoundFont 实例，按 MIDI 通道分配各自的 16 个立体声轨道输出。独立试听首次使用时加载自己的立体声实例，绕过工程图。混音快照和草稿沿用现有修订、撤销、恢复和资源包流程。MIDI 文件仍只交换 MIDI 内容，完整混音随工程或 `.icezip` 保存。逐轨输出依据 [FluidSynth 多输出接口](https://www.fluidsynth.org/api/group__audio__rendering.html)。

## 验证范围

- FluidSynth 2.6.2 输出探针将单个音符送往指定轨输出，其他输出样本为零。64 轨探针使用内置 Basic Waves，相同信号的绝对值总和为 166675.1283／166675.1284。四实例立体声与多输出 CPU 平均分别为 124／144 µs 每 256 帧，进程最大 RSS 约 25.4／25.8 MiB。该探针测量合成输出阶段。
- Ryzen 7 7735H，Linux amd64，48 kHz。64 MIDI 轨各两音，叠加 20 路 PCM。离线 256 帧循环基准分别为 0.458 ms（基础路由）和 0.612 ms（64 个内置效果，轮换五种效果），含 Go 测试调用边界。
- 同机通过隔离 PipeWire/PulseAudio 驱动运行实时短测，两组各 3 秒、566 次 256 帧回调。基础路由和效果组的回调 p99 分别为周期的 18% 和 22%，各自记录 0 次回调超时和 0 次互斥丢块。该测试只使用虚拟设备。
- 样本级测试覆盖逐轨 MIDI 隔离、并行脉冲对齐、循环跨界、侧链压缩、定位和循环自动化取值、峰值保持及复位。领域测试覆盖非法反馈环、事务回滚、对象 ID 冲突、范围隔离、恢复轨道依赖和便携工程校验。
- 全量 Go 测试、vet 和 Linux 构建通过。实际 MyGo/WebKit 窗口测试覆盖打开混音工作区、混音草稿落盘、应用、撤销、重做和 WAV 导出。导出帧数在补偿后与原区间相等，左声像自动化没有向右声道泄漏。
- A08 的第三方插件动态延迟等实际宿主测试随 E6 执行。A09 的物理设备 30 分钟连续回放和 xrun 仍待测。E3 的实体回环、设备与磁盘异常恢复及人工试听门槛继续独立追踪。
