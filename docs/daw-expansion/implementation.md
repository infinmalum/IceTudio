## 0. 操作范围与前置清单

| 操作 | 层与对象 | 约束与替换门槛 |
|---|---|---|
| KEEP | project/storage/app 的状态、稳定 ID、修订、事务、历史、恢复；CLI/IPC/Wails/Agent 全入口 | 新对象复用语义与测试，不建立 UI 私有权威状态 |
| KEEP | MIDI 导入导出、CC/meta/raw、时间图、音色、原生播放 | 扩展不能退化为纯音符；新引擎通过旧播放/控制/恢复测试后才接管 |
| KEEP | 五角色、委派、三执行模式、图/计划、审查/返工、复盘、预算、Skill、MCP、搜索 | 不因界面简化删除服务/表/CLI/IPC/测试；保持任务详情可达 |
| MOVE | tick/内部 ID、日志、预算等高级显示 | 进入精确属性/任务详情/开发者设置；原服务能力保留 |
| REPLACE | 用户可见分页、现有布局、必要时 GridSound 绘制适配 | 连续视口覆盖全部输入/选区/持续音/ghost/撤销/恢复/性能与原生 IME 后才移除旧载体 |
| REPLACE（有条件） | 当前音频渲染载体 | 新图满足 MIDI 控制追溯、试听、stop/seek/loop、实时更新及设备验收后再退役旧路径 |
| DELETE | 本轮清理记录中明确列出的历史文档正文 | 不删除代码、用户数据、当前契约、验收证据或许可证 |

此表是模块级规划，**不是未来按目录删除的授权**。任何 REPLACE 实施前必须生成具体调用者/注册、共享类型、存储字段、UI/CLI/IPC/工具与测试清单，记录新入口和逐项验收结果；不通过保留旧载体。不得删测试掩盖不等价。

## E0：基线与规格冻结

1. 读取本套文档、P0 契约、P1–P4 当前契约；记录 git revision、工作区差异、平台、依赖与已有验收缺口。
2. 建立 F01–F21 issue/工作包，每包关联需求、影响层、失败路径、验收证据；已有实现不重复建设。
3. 复跑适用的现有 Go/前端/真实工程服务测试；设备/模型/安装缺条件明确标记。确认现有失败是否基线问题，不借机清理无关代码。
4. 设计 1440×900、1280×800、200% 缩放的关键状态样稿，并由维护者走查编曲/编辑/审批/恢复流程。

退出门槛：基线报告、依赖清单、UI 关键状态、E1/E2 详细契约齐全。P2/P3 未完成原生验收仍保留，不能用新路线标成完成。

## E1：工作区与连续编辑体验（F01/F15/F16）

顺序：复现 data-view 选择器问题→修正布局→统一时间显示/吸附→面板显隐/比例→连续视口→快捷键与上下文入口。

影响：App、ProjectWorkspace、ProjectEditor、Transport、Arrangement、PianoRoll/usePianoRoll、projection/adapter、CSS 与布局偏好服务。前端投影可替换，领域对象不变。

交付：UI 规范全部基础布局；量化/移调调用现有确定性变换；长音跨视口编辑；播放头跟随；状态/恢复/Agent 范围视觉分层。先验证当前卷帘已有属性通道再补齐，避免重复 UI。

门槛：无模型新建→编辑→试听→保存重开→导出 MIDI；复制/删除/拖动/外部冲突/取消/ghost/IME 全回归；虚拟化性能满足验收矩阵，旧分页入口才退出。

## E2：MIDI 创作完整度（F01–F03/F08/F11/F21）

先冻结 Pattern/instance、clip split/merge/crop、选择器和新 ops schema，再实现跨轨/多片段原子操作、循环铺排、段落标记；接鼓组步进器、CC/弯音通道、音阶与和弦面板、节拍器/预备拍。

UI、CLI/IPC、Agent 新操作共用命令服务；增加 diff、inverse、查询分页、权限目标及资源限制。步进器只是同一音乐模型的新编辑视图。共享 pattern 编辑必须展示全部受影响实例；权限不足拒绝整组，不能只改一部分。

门槛：8 小节鼓/贝斯/和弦制作任务；循环/变拍/三连音精度与导出往返；GUI/Agent 同事务与共同撤销；新控件离线可用。

## E3：音频资产、录制与音频导出（F09/F20/F21）

依赖 E0，编辑接线依赖 E1。先定 tick/采样帧、资源引用/打包与恢复日志，再实现 WAV/FLAC 解码/编码、波形索引、音频片段、MIDI 输入/录制、输入音频录制和基础混音导出。解码库/设备层选型必须用截断、异常元信息、超大输入验证。

顺序：先离线确定性渲染→安全输出发布→设备输入与计时→录制 take 持久化→UI 电平/监听→中断恢复。先保证旧 MIDI 播放路线继续可用。

门槛：导出文件可重新导入且时长/音高正确；外部播放器复核；录制进程中断保留可恢复音频；输入/输出断连行为明确；未连接模型可完成全部流程。

## E4：混音图与自动化（F03–F09/F20）

依赖 E3。冻结独立轨输出、路由图、参数类型、automation target、状态快照与延迟补偿设计。先基准测量 FluidSynth 逐轨输出策略，再实施 Master/轨道/总线/发送/侧链与 Mixer。

先完成 gain/pan/meter 与 EQ/压缩/限制/延迟/混响基础，再接自动化读写模式、旁通/排序/预设。效果状态、自动化与路由均保存并可撤销。实时 callback 预算与离线渲染必须分别测量。

门槛：混音重开一致，路由非法环拒绝，侧链有效，延迟补偿脉冲测试，自动化在 loop/seek 时一致；CPU 过载有可诊断状态，不能静默停音。

## E5：采样、音频精修与素材浏览（F06/F09/F12/F17）

依赖 E3/E4。完成本地索引/标签/BPM/调性/预听、采样器区域映射与鼓垫、波形切片/反向/非破坏性拉伸、take/comp、音高校正的编辑入口。分析推断标签须可修改，不写成确定事实。

先验证算法/库许可与代表性素材，再定性能/音质门槛。拖入素材可选复制或引用；移动源文件时缺失定位不能删工程。在线目录接口保留到 E8，不用无来源样本填充演示。

门槛：素材→预听→拖入→编辑→混音→导出→携带工程重开；原文件不改，全部派生资源有引用与恢复路径。

## E6：插件宿主、音色深度与节点组合（F05/F07/F10/F14）

依赖 E4。选型并验证 CLAP/VST3 宿主及插件窗口/隔离方式，再接插件状态、自动化、预设、扫描隔离/黑名单、缺失恢复、冻结/解冻与离线渲染。建立至少两个独立厂商或开源实现的真实插件测试集；具体插件及下载需按权限流程确认。

Patcher 类节点组合复用音频图，新增 MIDI 处理/宏参数/组合预设；不复用 Agent 任务图语义。内置/可用插件应覆盖矩阵中的乐器和效果类别，每类有可演奏与重开导出证据；仅提供扫描功能不算音源目标完成。

门槛：插件崩溃不毁工程，状态与自动化恢复，实时/离线行为差异明确；平台不支持的格式显式告知。AU 随 E8 macOS 验收。

## E7：音乐辅助与音频 AI（F11–F13/F15）

依赖 E2/E5，分轨依赖 E3。完成和弦锁定/重生成、循环分层组合、四类 stem 分离、上下文帮助。模型/算法选择先记录许可、硬件、下载量、运行时间和测试集；不预设已安装模型或已具备版权许可。

作业冻结源资产与参数，支持取消/失败/重开查询；结果先候选试听，采用原子加入工程。远端执行逐次说明真实目的地和材料，仍受冻结上限与实时限制。Agent 对新增对象保持 scoped query/edit/preview 与共同撤销。

门槛：真实模型/算法完成任务，人工评价节奏/和声/伪影，记录失败案例；结构成功与音乐效果分别报告。

## E8：平台、在线服务与最终交付（F10/F16–F19/F21）

依赖相应功能阶段，不阻塞早期 Linux 编辑增量。Windows/macOS 音频和安装、AU、设备/控制映射与时钟同步、多显示器布局、自定义主题/控制面板、素材在线目录和显式云备份逐包实施。

服务商与资源授权先冻结；不能以 FL Cloud 规模为已承诺可复制的目录。缺商业接入条件保持相应矩阵项待交付，不把本地浏览器冒充在线服务。跨平台工程含缺失插件/资源清单；不承诺读取 FL 私有工程格式。

门槛：干净用户安装、无模型编辑、真实设备/插件/模型、长时间播放/录制、备份恢复和发行许可检查通过。各平台独立列状态。
