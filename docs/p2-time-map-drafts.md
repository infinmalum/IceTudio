# P2 时间图草稿持久化

状态：2026-10-18 实施前建立，现已完成下述限定代码与验证；见[验证记录](validation/p2-time-map-drafts-2026-10-18.json)。接续[时间图](p2-time-map.md)、[退出保护](p2-close-guard.md)和[工程提交恢复](p2-operation-recovery.md)；只覆盖速度/拍号表单，不代表全部输入或 P2 完成。

## 范围和所有权

ADD：应用数据目录的单条 `time-map-draft.json`、Go 读/比较替换/比较清除方法、Wails 门面、启动恢复入口与表单异步检查点。KEEP：权威工程、完整原子事务/撤销、原 opID 查询、冻结修订、权限及多 Agent 内核；无 schema、CLI/IPC/Agent 工具或依赖变化。REPLACE：仅对已持久化的时间图，退出问题由“丢弃”改为“保留草稿并退出”。未持久化成功的输入继续阻拦退出，不能用旧检查点冒充最新输入。

文件属于当前受宿主锁保护的数据目录，同一宿主内用互斥锁串行访问。一个数据目录同时保留一个时间图草稿；另一工程不得覆盖。记录是未应用输入，不是权威音乐或可自动重放的命令。保存原工程 ID/名称、PPQ、基础修订、原速度/拍号表及两张表的全部字符串行、稳定行 key、原微秒速度/显示 BPM。空值、重复 tick、非法 BPM 等表单实际进入 React 状态的字符串保留，恢复时不自动修正；浏览器尚未交给表单状态的临时输入法/number 控件文本不包含在承诺内。分页位置不属于音乐或草稿内容，恢复从第一页开始。

当前文件版本 1；payload 最大 4 MiB、封装文件最大 8 MiB，单个表格字符串字段最多 128 字节，标题最多 200 个 Unicode 字符，单表最多 100000 行。超限保存明确拒绝，保留当前内存输入和原文件，不截短数据。基础图必须是受支持、排序、无重复的原图；草稿行校验结构/范围上限和 key 唯一性，原显示 BPM 必须与原微秒值一致，不把用户正在编辑的无效音乐输入当作损坏文件。截断、未知版本/字段、非法结构、符号链接、目录及超大文件拒绝并保留，不能按“无草稿”覆盖。该大小上限不表示已验收极端规模表单的交互性能。

## 顺序、失败与恢复

1. 启动读记录完成前禁用时间图新建/恢复，关闭也须先完成或重试检查；其他已有工程能力不因此被删除。读取失败提供明确错误与重试，保留文件。
2. 打开表单冻结工程/修订/两张原图；修改后以 200ms 防抖异步写检查点，串行合并等待中的最新内容，应用/保留关闭会立即刷新。表单卸载时尝试刷新；工作区保留最新欲写内容及未确认请求，写入中/未确认仍阻拦退出并可重试。每次写或清除使用当前记录 token 作比较条件，并带新的请求 token；调用方不得把旧 token 当作新请求复用。重复同 token/同内容幂等，过期写/清除不能替换新记录。清除不删除文件，而是原子写入新 token 和空 payload，保留无音乐内容的屏障，阻止迟到的首次保存借“文件不存在”重新出现；空 payload 明确表示无活跃草稿。文件使用同目录临时文件、0600、文件 Sync、rename、目录 Sync。应答丢失后读取同 token/内容并同步核对，不能假定成功；仍未知时重试同一请求，之后才写新内容。工作区恢复/丢弃按钮在写入时禁用，不能与表单写入并发执行。
3. 显示“正在保留/已保留草稿，尚未应用工程”或具体错误；最新内容未获持久确认时，退出阻拦并提供重试。应用前等待最新检查点完成，再使用原基础修订走既有音乐事务；不重新定向或 rebase。
4. 正常表单关闭/Escape/重新载入的丢弃确认，成功匹配清除持久草稿后才关闭/载入；清除失败保留输入并显示重试。另提供“保留草稿并关闭”，等最新检查点确认后关闭。应用获提交成功确认后清除草稿；清理失败仍显示修改已保存，不能再次提交来代替清理。
5. 原生关闭检查中，最新检查点已确认的时间图询问“保留草稿并退出/继续编辑”；取消或 Quit 失败保留输入及文件。冻结期间复核草稿版本；后来的输入不使用旧退出确认。后台已保留但未打开的草稿不需要再次丢弃确认。
6. 重开显示原工程草稿入口，用户显式选择恢复；不自动应用。原工程和修订不可被当前选择替代，后来工程变更仍保留旧基础修订，应用冲突拒绝。存在待确认音乐操作时先查询原 opID；草稿可能已应用，不能根据草稿存在就重放。工程已删除时保留记录，说明无法恢复到已删除工程，允许明确丢弃，不重建工程。保留完整原图微秒精度，未编辑的导入值不因恢复被舍入。

## 验证和限制

验证真实 Go 文件及服务/SQLite 重建、token 幂等/冲突/并发/过期清除、损坏文件保留、文件路径错误、音乐未被草稿动作改写；浏览器验证空值/精度/增删行的写入与 reload 恢复、原工程/修订冻结、保存/清理故障、重试、正常关闭、应用与原生退出门面。真实 Wails 窗口、进程强杀/断电和磁盘硬件故障需另行验收；文件 Sync 与页面 reload 不替代这些证据。强杀可丢失尚未持久确认的最后输入；不得宣传任意时刻零丢失。

不包括力度、播放参数、普通数字框、设置/对话输入和指针预览的持久恢复，不改 MIDI 导入导出或外部副作用协议。草稿不会进入 Skill、跨对话记忆或模型材料。

本批验证：四项 Go 草稿测试及竞态检查（含 32 个并发开始）、真实 React→Go/SQLite 浏览器检查、原产品路径、7 项时间图计算、全量 Go 回归与 Linux 构建通过。浏览器音频/退出及 Wails 桥接仍为明确模拟，完整检查、计时及开发期测试修正见验证记录；不把页面 reload 或服务重建写成真实原生崩溃验收。
