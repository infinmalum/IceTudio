# 固定阶段流程

适合步骤事先确定的材料整理，例如分别分析材料 A/B，再汇总。用户仍只管理 Profile，阶段选择内置 worker 的配置槽位；宿主执行依赖，不调用 planner。

在 Profile 的“高级：执行组件”选择“固定阶段流程”，配置 worker 来源，再编辑“固定阶段”。每个阶段需要稳定 ID、worker 名称、任务和明确访问方式。可选“执行前向用户提问”对应 `inputPrompt`：前置阶段完成后，等待用户补充信息，再执行该阶段。依赖填写前置阶段 ID；无依赖的只读阶段可以并行，写入和未知副作用任务串行。列表顺序是就绪阶段的派发优先级，实际先后由依赖决定。

例如配置 worker 槽位 `analyst`，阶段填写：

| ID | worker | 任务 | 前置 | 访问方式 |
|---|---|---|---|---|
| analyze_a | analyst | 分析用户提供的材料 A，注明出处与缺失项 | 空 | read |
| analyze_b | analyst | 分析用户提供的材料 B，注明出处与缺失项 | 空 | read |
| combine | analyst | 汇总前置分析，保留分歧与来源 | analyze_a,analyze_b | read |

并发数设为 2 即可并行前两项。对话提交 A/B 和本次目标。worker 收到阶段任务、补充材料、本次用户目标，以及直接前置阶段的真实交付；不会自动读取主对话全部历史或长期记忆。只读阶段不能调用写入、命令、服务商原生搜索或未知副作用 MCP 工具；需要这些能力时选 write/unknown，宿主串行执行。实际可用能力仍受公共与 worker 工具选择、本机授权和逐次审批约束。

所有阶段都必需成功。模型的阶段结果受结构化契约与真实工具证据校验，但执行成功不代表独立验收通过。main 最后整理交付；可以配置必需 reviewer 和必要检查工具，审查未通过不标记完成。验收要求字段是要求声明，必要检查仍须真实执行，不能以口头保证替代。

保存会检查阶段 ID、worker 引用、缺失/重复/循环依赖、材料上限，以及覆盖阶段尝试、至少一次阶段模型调用、最终汇总和必要审查的最低预算。实际工具循环可能需要更多预算。阶段在根任务创建事务内初始化并冻结，后续 Profile 编辑只影响新任务。模型无法改写阶段，也不能跳过依赖、追加任务或重复领取。无后继阶段不只限于一个，全部成功后再汇总。

分享包包含阶段、依赖及普通配置，引用其他 Profile 的 worker 依旧按现有显式展平流程处理；不携带对话权限、审批或执行记录。恢复模板的 execution 配置组会恢复模板流程并移除自定义阶段，已有运行不受影响。CLI 使用现有 Profile 编辑与分享命令，任务状态沿用 `tasks status`。

阶段等待与续跑：

- 宿主先完成能执行的独立阶段，再按配置顺序提出就绪阶段的输入问题。等待不产生 worker 尝试，也不占用模型调用。
- 在对话框填写补充信息或附加文件，点击“补充并继续原任务”。原 Run ID、用户目标、已成功阶段、尝试和交付物保留。普通“新建任务”仍会从头执行整个流程。
- CLI 使用 `tasks status <runID>` 查看等待阶段，使用 `tasks continue <runID> --stage <stageID> --input '补充内容'` 回答并继续。无输入门槛的安全中断点使用 `tasks continue <runID>`；附件可通过桌面或 IPC `tasks.continue` 提交。
- 每个阶段输入只提交一次，绑定消息与阶段，重复或过时提交被拒绝。补充内容会提供给对应 worker 和最终汇总、审查/复盘；附件按原有结构化协议提供，累计仍限每任务8个、20MiB。
- 续跑沿用原任务的模型、组件、Skills 及资源快照、联网选项和权限上限，随后配置修改或删除不会扩大运行权限。当前本机授权仍可收窄权限；新授权不能突破原上限。
- 模型/工具/token/尝试预算不重置。已记录停止后的等待时间不计入执行时长，继续使用停止时剩余时长；停止前已耗尽预算则拒绝。硬退出的停止时间无法精确确认，恢复前经过的时间保守计入预算。
- 宿主重启仅保存状态，不自动执行。只有阶段均为成功或未领取、没有运行中组件或未知工具/原生联网结果，且会话没有后续任务时，才允许显式续跑。已失败/中断的 worker 尝试不重放；处置未知结果也不会把它变回未领取阶段。
- 每次续跑记录原状态、错误、输入消息和时间，执行计划中显示续跑次数。必需审查仍在全部阶段交付后执行。

目前不支持条件分支、自动重试或固定流程审查返工。阶段失败、审批拒绝或结果未知时停止后继并保留记录；需要新建任务时，应按已有副作用调整任务和配置。固定流程已通过模拟服务与交互验证，尚未完成真实模型场景验收。
