# IceTudio

IceTudio 的目标是 **AI native 音乐创作软件**：MIDI 编辑是原生能力，Agent 是与用户操作同一音乐工程的原生编辑者。用户可以在钢琴卷帘和编曲视图中手工创作，也可以让 Agent 修改选定音轨或片段；两者共享编辑事务、试听和撤销。

**当前处于转型执行阶段：P0 减法已完成（模板/Profile 库/分享/独立长期记忆已删，RuntimeConfig 就位，名称与构建产物统一为 IceTudio）；P1 工程模型与统一编辑事务已实现（[阶段设计](docs/p1-project-model.md)）：工程独立于对话保存，GUI（左栏工程管理、中间纯编辑器、右栏 Agent 栏）、CLI `icetudio projects` 与 Agent 工具（`project__query`/`project__edit`）经同一命令服务提交整组事务——修订冲突拒绝、操作 ID 幂等、撤销/重做、中断后可查询真实结果，MIDI 导入导出严格校验。P2 已接入钢琴卷帘、多轨片段编排画布与 Linux 原生播放，支持鼠标/键盘音符编辑、片段移动/末端拉伸、共享撤销、定位/循环、播放中更新，以及全部速度/拍号点与变拍小节尺。真实 PCM/PulseAudio 回调已测；2026-10-24 原生 Wails/WebKit 完整流程已有 13 项验证记录（范围与限制见下文）。设备异常、干净系统安装、物理音频延迟和听感仍待验收。** P2 及完整音乐产品尚未交付；RPM 版本约束与 AppImage 音色打包仍有实现缺口，见[安装契约](docs/p2-installation.md)。P3 已推进范围冻结、确定性变换及 main/worker 统一编辑网关，脚本模型通过真实执行引擎与 SQLite 验证局部编辑、审批拒绝、取消、冲突及共同撤销；音符候选差异、ghost 与临时原版/候选试听已接入并通过分层自动化测试；非音符/混合预览、真实模型与原生候选试听闭环仍未验收。

## 产品范围

- 工程与编辑工作区优先；不连接模型也应能编辑、试听和保存 MIDI。
- 保留模型接入、Agent、MCP、Skills 和联网搜索，扩展能力继续有清晰的启用与授权边界。
- 保留每个对话的历史、摘要和任务上下文，移除独立跨对话长期记忆。
- 保留反馈驱动 Skill 改进：记录有价值反馈和明确改进要求，提炼可检查、可修订、可回退的方法。
- 删除通用场景模板、Profile 管理/分享/生成产品及独立长期记忆。将内部角色/流程配置从 Profile 迁入 RuntimeConfig，普通用户无需配置工作流。
- 保留 main/planner/worker/reviewer/improver、多 Agent 委派、direct/dynamic/fixed 调度、审查/返工、复盘、任务图、预算和恢复。一个创作助手入口不等于删掉内部多 Agent 机制。

实施顺序为减法、工程事务、编辑试听、Agent 共同编辑、反馈改进与发布验收。首个可用闭环是：导入 MIDI → 手工编辑 → Agent 改写指定伴奏 → 差异试听 → 撤销或继续手改 → 保存重开 → 导出。

## 运行当前代码

技术栈为 Go/Wails/React/SQLite。module、前端包、绑定和产物已统一为 `icetudio`。以下命令运行当前转型中的音乐工作区，已实现范围和验收缺口见上文。

需要 Go 1.25+、Node.js/npm、Wails 3 CLI 和本机 Wails 桌面依赖。Linux+cgo 另需标准路径中的 FluidSynth 开发头文件/动态库（Debian `libfluidsynth-dev`，Arch `fluidsynth`），运行需要 `libfluidsynth.so.3` 及可用的系统音频服务；本机使用 PipeWire 的 PulseAudio 兼容服务。其他平台的音频门面明确返回不可用，整个平台尚未验收。`CGO_ENABLED=0` 仅能验证纯播放包的不可用路径，现有 SQLite 驱动也需要 cgo，不能据此运行完整编辑器。项目根目录执行：

```sh
wails3 dev
```

Linux 桌面构建：

```sh
wails3 task build
```

现有产物为 `bin/icetudio`，目前只有 Linux 构建验证记录。现有程序默认将数据放在二进制旁的 `data/`；不支持的数据库格式明确拒绝，不自动迁移或删除文件。工程已持久化到 `data/icetudio.db`（工程状态、编辑历史与撤销）。在工程传输栏点击“播放”会按需初始化原生音频；顶部传输栏含暂停（停止并保留位置）、小节/拍/BPM/拍号显示、撤销/重做与导出。左侧浏览器管理工程与音色：默认 GM 音色为随发行物内嵌的 MuseScore_General（MIT，见 assets/soundfonts/NOTICE.md；开发环境用 scripts/fetch-soundfont.sh 拉取固定哈希版本），可添加/移除/切换本地 SF2/SF3 并调整优先级，Basic Waves 永远最后兜底；`data/audio.json`（v2）保存音色列表与驱动，不支持的旧版本明确拒绝并保留文件，重置后恢复默认。生成的内置音色在 `data/audio/`，不参与音乐撤销。选乐器即可即时试听（含钢琴卷帘琴键点击），试听不写工程。 点击“编辑速度与拍号”可编辑全部变化点，点击“应用时间图”才会提交；关闭或 Escape 会询问是否丢弃已改草稿。进行中的手势/工程操作或未知保存结果会阻止本次退出。时间图输入会异步保留到 `data/time-map-draft.json`，界面区分草稿已保留与工程已保存；可“保留草稿并关闭”，重开后显式恢复到原工程/原修订。最新检查点未确认或失败时阻止退出，可重试；已确认时可“保留草稿并退出”，不自动应用到工程。正常表单关闭/Escape 的明确丢弃会清除活跃草稿内容，并留下无音乐内容的版本标记，拒绝迟到保存请求。检查期间冻结编辑；单值数字字段仍按既有失焦规则提交/拒绝。数字输入、音符力度与播放/循环/驱动等未应用输入保留在 `data/music-inputs.json`（Go 侧原子写，浏览器与真实窗口均验证保留/显式恢复/修订冻结）。实际 Wails 关闭（取消、保留草稿退出、重开恢复）与 SIGKILL 中断后结果查询已于 2026-10-24 在真实窗口验收；界面级界面状态（上次工程/视图/主题）在原生退出后可能滞留旧值，真实断电未验收，见[草稿契约](docs/p2-time-map-drafts.md)、[退出保护](docs/p2-close-guard.md)与[原生验证记录](docs/validation/p2-native-final-2026-10-24.json)。

GUI 音乐编辑、撤销和重做会先把待确认操作标记写入 `data/pending-project-edit.json`，成功后再发送音乐命令；提交确认后清除标记。重新打开时先读取记录，存在待确认操作就显示“查询保存结果”，只查询原操作，不自动重放；读取失败则禁用工程操作，并提供“重试恢复检查”。查询与清理针对原工程，切换工程不会更换目标。已提交但标记清理失败会明确保留“已保存”结论。损坏或未知版本记录保留文件并报错。该机制的服务/存储重开与浏览器 reload 已测，2026-10-24 另验证了真实原生 SIGKILL 后结果查询；真实断电仍未验收。时间图检查点与其他 P2 音乐表单的 `music-inputs.json` 恢复路径见上文，详见[提交恢复契约](docs/p2-operation-recovery.md)。

编排画布可拖动片段本体移动、拖动真实右端调整长度；重叠片段分行显示，跨页持续片段显示裁切标记。下方“片段”下拉框可选择当前轨道的全部片段，“显示选中片段”定位到其起点页；起点/长度数字框仍提供精确调整。手势开始冻结修订，冲突拒绝覆盖；调整长度不能截掉已有事件，可用工程撤销恢复。当前不支持跨轨拖动和多片段整组手势；整体原生窗口流程已验收，跨轨手势等局部体验见编排契约边界。

待审批的纯音符 Agent 编辑或确定性变换可先“查看音符差异”，再选择“在卷帘查看”、原版/候选试听、采用或丢弃。预览不写音乐，采用仍经原任务提交；期间手改使旧候选失效，提交后可用共同撤销。候选随待审批任务失效，不是独立保存的草案。2026-10-28 已通过真实工程服务浏览器流程及 FluidSynth 离线 PCM 测试；浏览器声音为 mock，本批原生窗口、物理听感和真实模型共同编辑未验收。

工程重命名自动保存，列表和工程标题随共享撤销/重做更新，重开保留名称。2026-10-18 已补正名称同步与依赖批量撤销的缺陷，并验证跨片段边界拉伸的整组撤销/重做；此前生成的错误历史不会自动重算，修正边界与验证见 [P1 §8](docs/p1-project-model.md#8-2026-10-18-名称持久化与依赖批量撤销修正范围)。

服务自动分配的音轨、片段、音符和控制事件 ID 现随实际操作写入历史；重做恢复原对象身份，后续编辑引用保持有效。四类对象的数据库重开、连续撤销/重做及浏览器/IPC 路径已测。此前漏记 ID 的旧历史不追溯修复，边界见 [P1 §9](docs/p1-project-model.md#9-服务分配-id-的重做稳定性修正)。

同一工程中，删除对象或撤销创建后，普通新建也不能再占用其 ID；要恢复原对象可使用共享撤销/重做。该检查覆盖导入形态的嵌套音符、控制及原始事件，已通过重开、失败回滚、并发与浏览器/IPC 验证。不同工程仍可使用相同显式对象 ID；此前已发生的错误身份复用不自动修复，历史规模的性能限制见 [P1 §10](docs/p1-project-model.md#10-工程生命周期内的对象-id-防复用)。
